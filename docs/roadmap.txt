# Roadmap Avelin

1. [DONE] Анализ проекта и удаление лишнего
   - Удалить устаревший каталог `Nova AI-Agent/`.
   - Убрать старые и сгенерированные артефакты, которые не должны жить в репозитории.
   - Проверить актуальность `frontend/`, `backend/`, `src/ai_agent/`.
   - Убедиться, что фронтенд собирается, а backend импортируется и видит API-маршруты.

2. [DONE] Обновление UI и названия агента
   - Заменить упоминания `Nova` на `Avelin`.
   - Подключить логотипы из `docs/light_logo.png` и `docs/dark_logo.png`.
   - Перевести интерфейс в строгую черно-белую палитру.
   - Добавить typewriter-эффект для ответов ассистента.

3. [DONE] Реализация темы
   - Добавить режимы: auto, light, dark.
   - Переключать тему через класс на `html` и CSS-переменные.
   - В auto-режиме выбирать темную тему с 21:00 до 07:00.
   - Менять вариант логотипа вместе с темой.

4. [DONE] Проверка и расширение функционала
   - Добавлено базовое логирование backend-запросов и ошибок.
   - Проверены `/api/bootstrap`, `/api/chat`, `/api/health`.
   - Обновлена документация по структуре, запуску проекта, логам и быстрой API-проверке.

5. [DONE] Настройка окружения
   - Проверены Node.js/npm для frontend: Node.js 24.15.0, npm 11.12.1.
   - Проверены Python-зависимости для backend: Python 3.13.9, `pip check` без конфликтов.
   - Установлен Rust toolchain: `rustc 1.95.0`, `cargo 1.95.0`.
   - Добавлен Tauri CLI в `frontend`: `@tauri-apps/cli 2.10.1`, команда `npm run tauri`.
   - Проверены Windows-компоненты для Tauri: Visual Studio Build Tools 2022/MSVC и Microsoft Edge WebView2 Runtime.

6. [DONE] Продуктовая основа: пользователи, сессии и SQLite
   - Перенесено хранение памяти, истории диалогов, настроек и пользовательских данных в SQLite.
   - Спроектирована минимальная схема БД: `users`, `sessions`, `auth_accounts`, `chat_threads`, `messages`, `notes`, `model_settings`.
   - Добавлен слой доступа к данным в backend, чтобы агент не работал напрямую с JSON-файлами.
   - Реализован простой механизм инициализации SQLite-схемы при старте.
   - Сохранена совместимость с текущей локальной памятью: добавлен одноразовый импорт `data/memory.json`.

7. [DONE] Регистрация, вход и профиль пользователя
   - Добавлена обычная регистрация: email/логин, пароль, имя пользователя.
   - Добавлены вход и выход из аккаунта, хранение сессии и проверка текущего пользователя.
   - Подготовлен OAuth-контракт через Google.
   - Подготовлен OAuth-контракт через ВКонтакте.
   - Разделены данные пользователей: история, заметки и настройки модели привязаны к конкретному аккаунту.
   - Добавлен базовый профиль в UI: имя, логин, провайдер входа, действие выхода.

8. [DONE] Настройки AI-модели и provider-ов
   - Вынесен выбор provider-а и модели из кода в backend-настройки и пользовательские настройки.
   - Добавлен API для получения списка доступных provider-ов и моделей.
   - Добавлен API для смены активной модели без правки кода.
   - Поддержан текущий `mock` как безопасный fallback-режим.
   - Подготовлена конфигурация для Ollama: адрес сервера, имя модели, проверка доступности через ответ provider-а.
   - Добавлены UI-настройки модели: provider, модель, статус подключения, краткое описание режима.

9. [DONE] Agent Architecture: функциональная база
   - Выделен `ai_agent` как независимый модуль, который можно запускать из CLI, backend и будущего desktop-приложения.
   - Зафиксированы основные сущности: `Agent`, `Task`, `Tool`, `Memory`, `Planner`.
   - Агентное ядро не зависит напрямую от FastAPI и UI.
   - Backend оставлен тонким слоем API, который передает команды агенту и возвращает результат.
   - Результат: Avelin становится не чатом внутри FastAPI, а отдельной системой принятия решений.

10. [DONE] Memory System: краткосрочная и долгосрочная память
   - [DONE] Short-term memory: хранить контекст текущей сессии, ограничивать окно сообщений и готовить сжатие истории.
   - [DONE] Long-term memory: хранить заметки пользователя, факты, результаты задач и важные решения.
   - [DONE] Использовать SQLite как первый стабильный слой хранения.
   - [DONE] Подготовить место для embeddings и семантического поиска на следующем этапе.
   - [DONE] Retrieval: искать релевантные заметки/факты/результаты задач и подмешивать их в prompt.
   - Результат: агент помнит опыт и использует его при выполнении новых задач.

11. [IN PROGRESS] Tool System: агент начинает действовать
   - Развит единый `ToolRegistry` для всех инструментов.
   - Инструменты описываются через JSON schema: имя, описание, аргументы, результат.
   - Добавлено выполнение инструментов через LLM tool-calls с валидацией аргументов.
   - Добавлено безопасное выполнение и логирование вызовов.
   - Добавлен внутренний task manager.
   - Добавлен первый файловый инструмент: безопасное чтение текстовых файлов из рабочей папки инструментов.
   - Добавлен второй файловый инструмент: безопасная запись текстовых файлов в рабочую папку без перезаписи по умолчанию.
   - Добавлен ограниченный shell-инструмент для проверок из allowlist внутри рабочей папки инструментов.
   - Добавлен безопасный HTTP-инструмент для GET/HEAD запросов к публичным http/https URL.
   - [DONE] Добавлен инструмент `create_presentation`: создание базовой `.pptx`-презентации внутри безопасной рабочей папки по JSON-структуре слайдов.
   - [DONE] Поддержать минимальный MVP презентаций: титульный слайд, agenda/структура, текстовые слайды, изображение + подпись, финальный слайд, единая тема оформления.
   - [DONE] Добавлена вставка локальных изображений в `.pptx` через `image_path` внутри безопасной рабочей папки.
   - [IN PROGRESS] Добавить входной пайплайн для презентаций: читать текст, `.txt`, `.md`, `.docx` и пользовательское ТЗ, выделять тему, аудиторию, цель, тон, количество слайдов, язык и ограничения по стилю. Сейчас поддержан прямой разбор пользовательского ТЗ из сообщения.
   - [IN PROGRESS] Научить planner строить исполнимый план презентации: собрать требования, предложить outline, подготовить контент слайдов, подобрать визуальные материалы, собрать `.pptx`, показать список созданных файлов.
   - Расширить HTTP/research-сценарии для презентаций: безопасно получать страницы, извлекать заголовки/текст, делать краткие выжимки и сохранять источники для последующей проверки.
   - Подготовить отдельный image/research слой: поиск подходящих изображений по теме, сохранение ссылок и лицензий, загрузка разрешенных изображений в рабочую папку после подтверждения политики источников.
   - [DONE] Добавить шаблоны презентаций: строгий деловой, учебный, pitch deck, продуктовый обзор, отчет/исследование; хранить их как пресеты цветов, шрифтов, сетки и типов слайдов.
   - [DONE] Добавить проверку качества презентации: нет пустых слайдов, текст не слишком длинный, у изображений есть источник, структура соответствует ТЗ, файл открывается как валидный `.pptx`.
   - Позже расширить до редактирования существующих презентаций: прочитать `.pptx`, извлечь структуру, заменить текст/изображения, добавить или переставить слайды без разрушения шаблона.
   - Инструменты связаны с первым execution loop для выполнения шагов задач.
   - Далее нужны retry, подтверждения опасных действий и расширение набора безопасных сценариев.
   - Результат: Avelin превращается из "болтуна" в исполнителя.

12. [DONE] Task System: сердце Avelin
   - [DONE] Введена сущность `Task`: id, статус, приоритет, описание, шаги выполнения, результат.
   - [DONE] Начат жизненный цикл: create, plan, execute, complete, fail, block/approve.
   - [DONE] Добавлена очередь задач с последовательным выбором следующей задачи.
   - [DONE] Добавлено хранение шагов и результатов выполнения.
   - [DONE] Добавлены внутренние инструменты для создания, просмотра, планирования, запуска и обновления задач.
   - Результат: пользователь дает список задач, а агент ведет их до результата.

13. [DONE] Planner / Reasoning
   - [DONE] Добавлен первый планировщик, который разбивает задачу на шаги.
   - [DONE] Добавлен первый execution loop: агент берет running-шаг, выбирает безопасный инструмент, выполняет действие, пишет observation и двигает задачу дальше.
   - [DONE] На первых сценариях поддержан выбор инструментов для файлов, `.docx`, shell-проверок и HTTP-запросов.
   - [DONE] Planner научен строить исполнимые `.docx`-планы: создать документ, затем показать созданные файлы.
   - [DONE] Начат цикл `think -> act -> observe -> repeat`: агент умеет создать план, запустить следующую задачу, выполнить шаг и отметить результат.
   - [DONE] Добавлен контроль выполнения для опасных действий: blocked-статус, action log и ручное подтверждение шага.
   - [DONE] Добавить retry для исправимых ошибок инструментов.
   - Результат: агент перестает быть API-оберткой и начинает вести работу как исполнитель.

14. [DONE] Context Orchestration
   - Добавлен `ContextBuilder`, который явно собирает prompt из текущей задачи, памяти и истории.
   - В prompt подмешиваются последние заметки пользователя и активная/следующая задача.
   - [DONE] Ограничивать размер контекста и приоритизировать последние сообщения, заметки, задачи и действия.
   - [DONE] Отделить системные инструкции, память, план задачи и наблюдения от инструментов.
   - [DONE] Подготовить summary для длинных сессий.
   - Результат: качество ответов и действий становится стабильнее на длинных задачах.

15. [DONE] Safety Layer
   - [DONE] Ввести ограничения на команды и файловые операции.
   - Добавлен sandbox для файловых инструментов и безопасная рабочая папка `TOOL_WORKSPACE_DIR`.
   - Добавлен лимит чтения/записи файлов и запрет записи за пределы рабочей папки.
   - Добавлен allowlist и таймаут для shell-команд, без произвольного PowerShell/cmd.
   - Добавлены ограничения HTTP-инструмента: только GET/HEAD, лимит ответа, таймаут и блокировка приватных/локальных адресов по умолчанию.
   - Добавлен журнал действий агента: какой инструмент вызван, с какими аргументами, какой статус и результат получены.
   - Последние действия подмешиваются в prompt как наблюдения для следующих шагов.
   - [DONE] Запрашивать подтверждение пользователя для потенциально опасных операций.
   - Результат: Ollama остается "мозгом", а Avelin становится контролируемой системой действий.

16. [DONE] Chat Workspace: история, несколько чатов и очистка
   - Добавить полноценную сущность `chat_threads`: title, status, archived_at, deleted_at, pinned, project_id, timestamps.
   - Добавить API для списка чатов пользователя: активные, архивные, удаленные/скрытые.
   - Добавить создание нового чата и переключение активного чата без потери истории.
   - Добавить переименование чата и автоматическое название по первым сообщениям.
   - Добавить очистку текущего чата: удалить сообщения из выбранного thread, не удаляя заметки, задачи и долгосрочную память.
   - Добавить удаление чата с подтверждением и безопасным поведением: сначала soft-delete/скрытие, позже окончательное удаление.
   - Добавить архив чатов: архивный чат остается доступен в истории, но не участвует в текущем short-term context и не подмешивается в prompt.
   - Обновить `MemoryStore`, `ContextBuilder`, backend и UI так, чтобы все операции работали с выбранным `thread_id`, а не только с `default-thread`.
   - Результат: пользователь может вести несколько независимых диалогов как в ChatGPT, очищать текущий чат и возвращаться к старым веткам.

17. [DONE] Chat Projects: структура рабочих областей
   - Добавить сущность `projects`: id, user_id, title, description, status, created_at, updated_at.
   - Добавить API и UI для создания, переименования, просмотра, архивирования и удаления проектов.
   - Добавить привязку чата к проекту и удаление чата из проекта без удаления самой истории.
   - Добавить список чатов внутри проекта и отдельный список чатов без проекта.
   - Поддержать project context: краткое описание проекта, выбранные заметки и активные задачи проекта могут подмешиваться в prompt только для чатов этого проекта.
   - Подготовить будущую привязку задач, заметок, файлов и рабочих артефактов к проекту.
   - Результат: Avelin получает структуру рабочих областей, где разные темы не смешиваются между собой.

18. [DONE] Правила памяти для чатов, архивов и проектов
   - Разделить short-term context по чатам: текущий чат видит только свою историю сообщений.
   - Разделить long-term memory на глобальную память пользователя и проектную память.
   - Не добавлять архивные чаты в prompt автоматически.
   - Дать пользователю явные действия: "запомнить из этого чата", "не использовать этот чат как память", "перенести в проект".
   - Добавить retrieval с учетом scope: current_chat, current_project, global.
   - Добавить настройки приватности памяти: какие чаты/проекты разрешено использовать для долгосрочного retrieval.
   - Обновить UI, чтобы было видно, влияет ли чат на память агента.
   - Результат: история становится управляемой, а память агента не загрязняется случайными или архивными диалогами.

19. [DONE] GitHub-стратегия: разделить сайт и приложение
   - Развести продукт на две независимые линии разработки: сайт Avelin и desktop-приложение Avelin.
   - Оставить приложение агента в основной ветке и переименовать `master` в более понятное имя, например `app` или `desktop-app`.
   - Создать отдельную ветку для сайта, например `website`, чтобы UI сайта, landing, новости и страницы загрузки не смешивались с кодом приложения.
   - Зафиксировать правила: приложение развивается в app-ветке, сайт развивается в website-ветке, общие материалы бренда и документации синхронизируются осознанно.
   - Подготовить README/roadmap-раздел с объяснением, где находится сайт, где приложение, как делать релизы и pull request.

   - Сформировать две визуальные системы: публичный сайт для презентации продукта и рабочий интерфейс приложения для ежедневного использования.

   - Для приложения переработать текущий UI как рабочую среду агента: чат, память, проекты, файлы, настройки модели, обновления и статус локального ядра.
   - Разделить компоненты, тексты и навигацию сайта и приложения, чтобы marketing UI не перетекал в рабочий desktop-интерфейс.
