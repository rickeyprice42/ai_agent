# GitHub-стратегия: приложение и сайт

Avelin разделяется на две независимые продуктовые линии:

- `app` - desktop-приложение агента: `frontend/`, `backend/`, `src/ai_agent/`, `src-tauri/`, локальная модель данных, инструменты и релизы приложения.
- `website` - публичный сайт: landing, новости, страницы загрузки, публичная документация, release notes и код, связанный с хостингом.

Такой расклад не дает рабочему интерфейсу агента превращаться в маркетинговый сайт, а экспериментам сайта - попадать в релизный путь приложения.

## Владение ветками

- Приложение агента развивается в `app`.
- Публичный сайт развивается в `website`.
- Общие бренд-материалы и документация синхронизируются осознанно: через небольшой cherry-pick или отдельный сфокусированный pull request.
- Website-only изменения интерфейса не попадают в `app`.
- Backend, локальное хранилище, Tauri и runtime агента не попадают в `website`, кроме случаев, когда сайту явно нужны публичные release metadata или документация.

## Локальная настройка веток

В репозитории заведены локальные ветки для разделения:

```powershell
git branch --show-current
git branch --list app website
```

Рекомендуемый первый push, когда remote готов:

```powershell
git push -u origin app
git push -u origin website
```

После появления `app` на GitHub стоит сделать ее default branch в настройках репозитория. Старую remote-ветку `master` лучше оставить только временно, пока локальные копии и автоматизация не переедут на новую схему.

## Правила pull request

- PR для приложения открываются в `app`.
- PR для сайта открываются в `website`.
- Если изменение затрагивает обе линии, лучше делать отдельный PR для синхронизации.
- В PR нужно явно указывать, какие общие assets или документы были скопированы/синхронизированы.
- Релизные PR стоит держать небольшими: релиз приложения включает desktop build, installer metadata, checksums и release notes; релиз сайта включает обновление download page и публичные тексты.

## Релизный поток

Для desktop-приложения:

```powershell
git checkout app
cd frontend
npm run build
npm run tauri -- build
```

Из app-релиза публикуются установщик, checksums и release notes.

Для сайта:

```powershell
git checkout website
```

Обновляются landing, страницы загрузки, публичные release notes и hosting config. Деплой сайта должен использовать готовые артефакты app-релиза, а не пересобирать desktop-приложение.
