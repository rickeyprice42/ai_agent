# Длительная работа по утверждённому плану

Для большой просьбы агент может вызвать `propose_long_task`: карточка в чате показывает цель, этапы, критерии проверки и конечные лимиты. Черновик не создаёт исполняемую задачу. Только кнопка «Утвердить и начать» с текущими revision/digest ставит план в очередь. Повторный клик не создаёт второй запуск. Общие рабочие пространства пока не поддерживаются этим режимом; личные проекты поддерживаются.

После утверждения Agent работает в отдельном сохраняемом диалоге того же проекта. Каждый этап использует существующие durable run, lease, heartbeat, checkpoints и approval. Файлы, точные изменения и запуск проверок ограничены `outputs/tasks/<plan-id>/`. Начальное утверждение плана не разрешает исполнение программ: `run_code_check` запрашивает отдельное подтверждение. Публикация, установка зависимостей и произвольный shell не входят в этот первый набор инструментов.

Между фазами сохраняются дословная исходная просьба, утверждённая цель, критерии и выдержки завершённых этапов. Старые технические tool-сообщения не занимают новое окно целиком; оригиналы остаются в истории, файлы можно читать заново. На следующую порцию наблюдений резервируется часть окна. После crash незавершённое неизвестное действие не переигрывается автоматически. Завершённые фазы и ожидание конкретного approval переживают пересоздание Agent.

Пауза и отмена изменяют run/task атомарно и не перезаписывают уже завершившуюся работу. При паузе во время вызова нужно дождаться его ограниченного timeout. Возобновление неизвестного действия блокируется с объяснением; ожидание approval сохраняет тот же запрос, не выдавая скрытое разрешение. Есть конечные лимиты времени, действий, ошибок и оценочных токенов; денежный лимит без подтверждённого billing не обещается.

Отчёт о прошедшем локальном дне собирается из checkpoints автоматически по IANA-поясу устройства, указанному при утверждении. После простоя сервер догоняет закрытые дни; после завершения прекращает ежедневные отчёты. Подтверждённые действия, проверки, файлы, блокеры и следующий шаг видны в существующем разделе отчётов/уведомлений. Работа и формирование отчётов требуют включённого сервера; браузер пользователя может быть закрыт.

## Приёмка первой версии

- Изолированные регрессии проверяют отсутствие действий до утверждения, digest/CAS, изоляцию пользователей/файлов, отдельное разрешение исполнения, завершение фаз после restart, отмену/паузу и дневные границы часового пояса.
- Реальный маленький CLI-прототип выполняет три настоящих unittest только после отдельного approval.
- Реальный OpenAI-прогон небольшой браузерной игры выполняет три фазы с пересозданием Agent между ними. Первые прогоны выявили переполнение контекста и ошибку относительного пути; после исправлений цикл завершился за 151,11 секунды.
- Фраза модели «готово» без выполненного инструмента не завершает фазу. Факт исполнения этапов не доказывает все смысловые критерии: результат требует самостоятельной проверки. Этот короткий тест не доказывает многодневную автономную разработку произвольной игры до релиза.

API: `GET /api/chats/{id}/plans`, `POST /api/long-tasks/{id}/decision`, `POST /api/long-tasks/{id}/control`. Общий `execute-next` не забирает планы фонового Agent. Существующие незапрошенные task drafts не запускаются автоматически.
